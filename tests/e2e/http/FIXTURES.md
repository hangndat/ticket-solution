# HTTP fixture contract

Runner dùng `E2E_MANIFEST` schemaVersion 1 và chỉ đọc `cases[ID].accounts` của từng ca. `runtime.httpClientId` = `e2e-http`, `runtime.httpClientSecret` do harness cấp trong manifest private. Token lấy bằng confidential password grant từ Keycloak realm `e2e-<runId>`; runner không in credential/token/manifest. API và Auth origins phải HTTPS. TLS trust và DNS preload do coordinator cấp cho process Node.

| Case    | Fixture bắt buộc                                                                                                                                                                                                                                                            |
| ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SEC-01  | Tenant/event của ca; `accounts.owner` có `report.read` và assignment event; `data.foreignTenantId`, `data.foreignEventId` là UUID thật không có quyền của owner.                                                                                                            |
| SEC-02  | Cùng seed isolation như SEC-01 (`foreignTenantId`/`foreignEventId`). Không credential trong log. Kiểm Set-Cookie OIDC trên web + portal staff/platform login (host-only, HttpOnly, Secure, SameSite=Lax); portal/web BFF Origin thiếu/sai → deny; CSRF double-submit portal; `e2e-http` vs `e2e-http-platform` audience không hoán đổi trên `/v1` vs `/v1/platform/*`; Origin header không thay bearer authz. |
| SEC-03  | Tenant/event seed chung (chỉ cần `tenantId` cho query admin migration). Không credential trong log. Kiểm web BFF login/refresh (HTTPS + direct upstream qua `runtime.upstreamPorts`), marketing host bounce, portal staff/platform OIDC login, legacy GET/HEAD `/admin` → portal, và API `/v1/health` với Host/forwarded giả. |
| SEC-04  | Event mở check-in; `ticketId` ACTIVE (seed redeem `code`); `secondCode` còn quota cho redeem rate probe; scanner/owner/cs/attendee như GATE-03. Harness prime `notification_rate_counters` tại limit−1 (resolve/redeem/gate.reserve/receipt/import list) cho bounded 429. Kiểm 429 envelope/code/retryable theo endpoint; `Retry-After` chỉ trên import list; receipt vs offline-sync bucket tách; CS resend cooldown 429; admission token sai không tăng check-in. |
| SEC-05  | Event published; `accounts.attendee.username` bắt đầu bằng `=` (formula email) và ticket ACTIVE (`ticketId`) cho export CSV guard; `data.configVersion` cho config save stale gate; `sourceId`/`ticketTypeId` cho import upload/preview; `data.xssPersistMarker` cho public projection unchanged khi CONFIG_UNSAFE_MARKUP. Không credential trong log. |
| SEC-06  | `data.auditCount`=105 audit rows (owner actor) gồm 1 row mang `data.secretReason`/`data.secretEmail`/`data.secretHmac` trong `reason`/`sanitized_diff`; `data.codesSourceId`/`data.codesTicketTypeId` có 110 code AVAILABLE (`data.codesBulkCount`) để kiểm limit cap; `data.probeRawCode` là raw code đầu bulk để kiểm `q` search không echo. Owner có `report.read`+`inventory.import`; scanner không có quyền này cho nhánh deny. Kiểm audit/codes list projection, cursor opaque, limit cap 100, lỗi 404/422 không leak, và Cache-Control không `public` trên report/me-tickets/gate-session. Không credential trong log. |
| AUTH-03 | `code` AUTO còn dùng được; `accounts.unverified` emailVerified=false, `accounts.attendee` verified, `accounts.owner` report.read; `data.formVersion`, `data.termsVersion`, `data.answers` khớp published form. Attendee issue được cùng code sau lần unverified bị từ chối. |
| GATE-01 | Event có scanner `gate.confirm`, owner `event.update` và assignment; `data.gateName` chưa tồn tại, `data.foreignEventId` là event khác owner/scanner không được assign; `data.foreignGateId` là cổng có thật ở event khác trong cùng tenant.                                |
| GATE-03 | Event mở check-in; `ticketId` ACTIVE; scanner `gate.confirm`, owner `report.read`, attendee không có assignment. Invalid random ticket gây `gate.reject` audit.                                                                                                             |
| DB-03   | `code` AUTO còn dùng được; attendee verified, owner report.read; published consent `data.formVersion`, `data.termsVersion`, `data.answers`; quota/counter có đủ một suất.                                                                                                   |

Mỗi ID cần tenant/event/mã/tài khoản riêng. Seed không được tạo ticket trước cho `AUTH-03`/`DB-03` bằng `code` này; test tự issue. Các ca HTTP không phụ thuộc Playwright hoặc test khác. Thiếu manifest, key hoặc account làm test fail rõ `BLOCKED`, không skip.
