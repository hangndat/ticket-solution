## Security assessment

### Threat / abuse cases

| Case | Verdict on SHA `0d5b52a` |
| --- | --- |
| Cross-tenant leak via global lookup | Lookup uses digest aliases + groups; tenant projection via `withTenant(target.tenantId)`. **Acceptable** for designed boundary. Resolver remains **app-layer SQL**, not PostgreSQL SDF (architecture §4.1) — **known gap**. |
| Enumeration (invalid vs ambiguous) | `assertRoutableTarget` → generic `CODE_INVALID`. Closed window can return `REDEMPTION_WINDOW_CLOSED` (distinct). |
| Resolve token forgery / replay | HMAC-SHA256, `timingSafeEqual`, 15m TTL, binds actor + routing group + tenant/event/code. `verifyResolveTokenForIssue` re-validates alias group — **sound when token is verified**. |
| **Bypass resolve on issue (global)** | **`verifyResolveTokenForIssue` only if header present** (`issue.ts` `runIssueBusiness`). `RESOLVE_TOKEN_REQUIRED` exists in contracts/`issue-error.ts` but is **never thrown**. Attacker with tenant/event/code (e.g. from prior resolve) can issue **without** token — **should-fix before `SINGLE_CODE_RESOLVE_GLOBAL=1`**. |
| Rate limit abuse | Resolve: `tryConsumeRateLimit` 30/10m per **OIDC user id** only. **No** IP bucket, **no** per-hmac failure bucket (AC-6). |
| Raw code in logs/URL | Resolve path does not log `body.code`. iOS draft intent: in-memory only, redacted debug helper, tests for account switch — **good**. Web BFF passes code in JSON body only. |
| RLS on `code_routing_*` | **Improved** vs prior review: migration `202610200002` ENABLE+FORCE RLS; groups/aliases global policies; **candidates tenant-isolated**. `rls-catalog.test.cjs` registers global tables. |
| Global gate | `isSingleCodeResolveGlobalEnabled` + `countAmbiguousRoutingGroups` → 503 `RESOLVE_DISABLED`. Prod flag off per PR/UAT — **appropriate**. |
| Import registry drift | `importCodes` wires `routingRegistry` when pepper + fp secret configured; **silent skip** if env misconfigured — codes import without aliases (**ops risk**). |

### Security verdict

**PASS with known gap**

**Blockers before enabling global resolve** (staging/prod flag on):

1. Enforce mandatory resolve token on global issue path (`RESOLVE_TOKEN_REQUIRED` when flow is global or when code has routing alias / global flag on).
2. AC-6 rate limits: IP + per-digest failure buckets on resolve (and issue where applicable).

**Hardening (non-blocking for merge with flags off):** SDF resolver; integration tests for authz/rate-limit; ensure access logs redact resolve bodies.
