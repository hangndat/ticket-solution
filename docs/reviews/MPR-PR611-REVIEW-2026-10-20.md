## Fix assessment

### Root cause (#610)

- `walletFetchScopeFromEnv()` luôn `return { kind: … }` — object literal mới mỗi lần gọi.
- Trước fix: `const fetchScope = walletFetchScopeFromEnv()` mỗi render → `fetchScope` lọt deps `refresh` (`useCallback`) → `useEffect([hydrateFromCache, refresh])` re-fire → `probeMeTickets` lặp + UI nháy.

### Shipped fix

- `VerifiedWallet`: `const fetchScope = useMemo(() => walletFetchScopeFromEnv(), []);` — **chỉ** ổn định reference qua render trong lifetime component.
- **Không** đổi: `probeMeTickets` / `decideTicketSyncApply` / cache hydrate / offline-cache / unauthorized logout / persist / bind flow — body `refresh` và quyết định sync giữ nguyên; chỉ identity của `fetchScope` trong deps thay đổi.

### Helper `meTicketsFetchScopeKey`

- Export mới: string key `owner` / `tenant:<id>` — documented alternate cho React deps.
- Screen **không** wire key vào deps (dùng `useMemo` object). Helper phục vụ test + guideline; không đổi runtime API path.

### `getTenantId()` / empty `useMemo` deps

- `getTenantId()` đọc `process.env.EXPO_PUBLIC_TENANT_ID` + baked `expoConfig.extra.ticketPublic.tenantId` — giá trị bake/Metro-time, không phải store đổi giữa các render trong 1 session app.
- Empty deps `[]` khớp model: scope env tĩnh trong lifetime `VerifiedWallet`. Không có path product đổi tenant UUID mid-session mà không remount identity/wallet.
- Residual theoretical: nếu ai đó mutate `process.env` lúc runtime mà không remount — `useMemo` không refresh. Không phải hazard pilot; chấp nhận được.
