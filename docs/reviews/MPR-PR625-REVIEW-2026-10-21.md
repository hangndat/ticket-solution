## Security / abuse (trọng tâm Spec)

### Rate limit PostgreSQL

- **Migration mới:** không — tái dùng `notification_rate_counters` + `tryConsumeRateLimit` (N1 migration `202610170009`).
- **RLS:** bảng có RLS `ticket_runtime` theo `app.tenant_id`; counter API dùng `tenant_id` cột làm **partition key** (userId hoặc UUID synthetic từ IP hash), cùng mô hình đã có cho `/redemptions/resolve` — không mở rộng tenant data chéo.
- **Hiệu năng:** một transaction INSERT…ON CONFLICT + UPDATE có điều kiện mỗi request bị limit — chấp nhận cho MVP hourly cap.
- **IP / X-Forwarded-For:** `trustProxy: false` trên Fastify; key IP từ `req.ip` (không tin header client). **Hạn chế vận hành:** sau reverse proxy chưa cấu hình trust proxy, limit theo IP là IP proxy chung — ghi nhận hardening follow-up, không chặn AC PR.
- **DB null / lỗi:** `if (!db \|\| limit < 1) return` → **fail-open** khi không có DB (unit test); production `fromEnv` có DB. Lỗi PG không bắt → request có thể 500 (fail-closed tạm thời), không bypass limit im lặng.

### `packages/contracts/src/index.ts`

- Thêm `IDENTITY_ERROR_CODES.OIDC_UNAVAILABLE` — **additive**, không đổi semantics code hiện có.
- **Consumer (web/portal/mobile):** không bắt buộc đổi compile-time; mobile `probeMe` coi mọi `status >= 500` là `unreachable` (không logout như 401) — **đúng** với refresh/session boundary mới.
- **Coordinator:** thay đổi nằm slice contracts do coordinator sở hữu — **ghi nhận** cho release notes / codegen; **không** phá tương thích, không yêu cầu chặn merge nếu AC backend đã đủ.

### OIDC / mobile

- 503 + `retryable: true` + code `OIDC_UNAVAILABLE` không bị mobile map thành `unauthorized`; `verifyViaMe` → `CREDENTIAL_UNREACHABLE` khi 5xx — giữ credential, không revoke nhầm.

## Architecture (TECHNICAL-DESIGN.md)

- Rate limit app-layer bổ sung cho Caddy/edge (TD § edge controls) — phù hợp “default per-user caps”, không thay waiting room.
- Lỗi identity phân biệt misconfig (503) vs unauthenticated (401) — khớp hướng fail-closed + retry transport.
