## DoD (functional)

### Refresh + consumers

- Login paths (`useAttendeeSignIn`, `ConfiguredAccount`) persist `refreshToken` + `expiresIn` via `establish(..., tokens)`.
- SecureStore holds JSON envelope when refresh present; legacy plain access-only strings still parse.
- `getCredential()` → `ensureFreshAccessToken()`: near/expired access (+ skew 60s) refreshes, writes new envelope, returns **access token only**.
- Graph `callers_of(SessionBoundary.getCredential)`: 20+ product call sites (wallet, gate, redeem, push, staff-eligibility, account-deletion, theme) — **không cần** sửa từng fetch site; boundary là choke point đúng Spec.
- Không thấy consumer ngoài `session-boundary` parse envelope / đọc `secureCredentialStore` thô làm bearer (APNs `store.read` là registration store khác).

### Failure modes

| Case | Behavior | Test |
| --- | --- | --- |
| Refresh OK | Persist new access(+refresh), stay verified, return new access | `getCredential refreshes expired access token transparently` |
| Refresh fail auth (`invalid_grant` / config) | `invalidate(signed-out)` + `store.clear()` — không giữ verified giả | `refresh auth failure…` + `restore refresh auth failure…` |
| Refresh fail network | SessionBoundary **không** self-logout; `getCredential` trả prior access; restore → `unreachable` + giữ credential | `refresh network failure…` + `restore refresh network failure…` |

### restore() cold start

- Expired access + valid refresh + online: `ensureFreshAccessToken` refresh → `verify(access)` → `verified` (code path đúng; **thiếu** unit test dedicated — xem gap).
- Auth refresh fail: signed-out + clear — không elevate verified.
- Network refresh fail: `unreachable`, publish signed-out UI, **giữ** SecureStore — khớp `CREDENTIAL_UNREACHABLE` (không wipe oan).

## Security review

### Threats examined

1. Token leakage via logs  
2. SecureStore accessibility downgrade  
3. Refresh grant transport (query leak) + clientId/discovery  
4. Keycloak refresh-token rotation race (double refresh)  
5. Cold restore false login / false logout  
6. Envelope treated as raw bearer by consumers  

### Findings

| # | Severity | Finding |
| --- | --- | --- |
| S1 | **Should-fix / known gap** | Khi refresh **network** fail trong lúc đã `verified`, `getCredential()` vẫn trả **access token cũ** (có thể đã hết hạn). Consumer ví dụ `my-tickets` → probe 401 → `logoutAndClearWalletArtifacts` — có thể **logout oan** nếu IdP token endpoint down nhưng API vẫn trả 401 cho bearer hết hạn. SessionBoundary tự nó không logout (đúng test), nhưng end-to-end AC “network ≠ logout” chưa kín. Mitigate follow-up: không hand expired bearer khi refresh network-fail (null / signal riêng), hoặc consumers không logout trên 401 ngay sau refresh unreachable. |
| S2 | Hardening | `isAuthFailure` coi mọi `status === 400/401` là auth — gateway proxy lỗi có thể false-positive clear session. |
| S3 | Hardening | `reason: 'config'` (thiếu issuer/clientId) được xử lý như auth (clear). Bake Expo thường ổn; edge cold-start misconfig có thể wipe. |
| S4 | Coverage | Không có unit test `restore()` refresh-OK → `verified`; không có test coalesce `refreshInFlight` dưới concurrent `getCredential`. Code single-flight có (`refreshInFlight`). |

### PASS security controls

- **Không** `console.*` / logger token trong diff scope; `oidc-refresh` ghi chú never log token material.
- `secure-credential-store.ts` giữ `WHEN_UNLOCKED_THIS_DEVICE_ONLY` + cùng key/service — **không** hạ cấp accessibility. Refresh token nằm trong JSON envelope cùng keychain class (cố ý; tăng bề mặt secret nhưng không downgrade flag).
- Refresh dùng `AuthSession.fetchDiscoveryAsync(issuer)` + `refreshAsync({ clientId, refreshToken }, discovery)` — expo-auth-session `TokenRequest` dùng **`method: 'POST'`** + `grant_type` trong body (đã xác nhận `apps/mobile/node_modules/expo-auth-session/build/TokenRequest.js`), không leak refresh qua URL query.
- Concurrent refresh: `refreshInFlight` coalesce + `storageQueue` serialize writes; generation guards sau refresh/write — giảm race rotation Keycloak (một InstanceBoundary / app singleton `session`).

## Findings summary

- **Blocker:** không.
- **Should-fix (known gap S1):** cascade 401 logout khi refresh network-fail trả expired bearer — ghi rõ; không chặn merge nếu coordinator chấp nhận gap + follow-up Issue, hoặc yêu cầu fix trước merge.
- **Nit / hardening:** S2–S4.

## Known gaps (không nuốt AC cốt lõi SessionBoundary)

1. End-to-end “network refresh fail ⇒ no logout” chưa được bảo vệ khỏi consumer 401 logout (S1).
2. Thiếu test restore refresh-success và concurrent refresh coalesce.
3. Không device UAT cold-start refresh trong phiên reviewer (CI + unit đủ cho code DoD; physical session riêng nếu cần pilot).
