## (1) Chất lượng test at-least-once

**Không phải test giả:** dùng `relayOutboxOnce` / `processClaimedOutbox` từ `dist`, Postgres 18.1 thật, migrations đầy đủ, fixture redeem + device token + outbox `TicketIssued`.

- **Crash trước ack:** UPDATE thủ công `notifications` push (và email) về `PENDING`, outbox về `PENDING` — mô phỏng trạng thái sau I/O APNs thành công nhưng chưa persist ack. Retry gọi lại adapter (`getSends` tăng), sau đó assert `ACCEPTED`.
- **Dedup:** lease outbox giả lập, `processClaimedOutbox` với push đã `ACCEPTED` — `deliverTicketIssuedApns` skip device (`outbox.ts` L728–729); test assert không gửi lần 3.
- **Provider throw:** adapter flaky ném lỗi lần 1 (không ack DB); `relayOutboxOnce` lần 2 hoàn tất — nhánh retry outbox thật, không stub luôn pass.

**Lưu ý (known gap nhỏ, không chặn PASS):** limitation ADR *email `ACCEPTED` + push `PENDING` → short-circuit complete* khớp `processClaimedOutbox` (email `ACCEPTED` → `markOutboxCompleteFenced` L344–346, không vào `push_pending`). PR **không** có test assert hành vi short-circuit; case 1 cố ý reset email về `PENDING` để vào lại đường push. Phù hợp phạm vi Issue (ghi limitation + test at-least-once chính).

## (2) ADR-12 vs `outbox.ts` (merged #641)

| Khẳng định ADR | Code |
| --- | --- |
| I/O APNs ngoài transaction (H2) | `deliverTicketIssuedApns` — send rồi ack trong tx riêng (L769–836). |
| Retry sau crash có thể trùng tối đa 1 lần/device đến khi push `ACCEPTED` | Pending push được gửi lại; `SENT`/`ACCEPTED` skip (L728–729). |
| Email `ACCEPTED`, push `PENDING` → short-circuit complete, không gọi APNs | L344–346 khi chỉ xét channel email. |
| Push lỗi ack có thể không retry đến `push_pending` | Đúng với short-circuit trên; ADR không hứa exactly-once. |

**Không hứa quá mức** so với implementation.
