## (1) Rate limit + RLS

**Trước:** transaction gọi `tryConsumeRateLimit` không set `app.tenant_id` → INSERT/UPDATE `notification_rate_counters` vi phạm RLS → Nest 500.

**Sau:** `consumeRateLimitInTenantContext` set session trong **cùng** transaction, `local=true` (transaction-scoped) — khớp pattern test DB (`membership.test.cjs`, `withTenant`).

| Chủ đề | Đánh giá |
| --- | --- |
| Synthetic `tenant_id` vs event tenant | **By design** (PR #625 / N1) — partition abuse counters; không map tới tenant sự kiện. |
| Cross-tenant leak | **Không** — RLS chỉ thấy hàng có `tenant_id` = session; IP A không ghi vào namespace IP B (hash UUID riêng). |
| User rate limit | `tenantId = userId` — session bind user partition; không mở row tenant khác. |
| DoS qua khoá rate | Counter PK `(tenant_id, bucket_key, window)` — flood IP tạo nhiều synthetic tenant_id (chi phí storage) là trade-off IP cap chuẩn; không làm hỏng counter tenant sự kiện thật. |
| Fail-open `!db` | Giữ nguyên từ #625 — production có DB; không đổi trong PR. |

## (2) CSP runtime (`proxy.ts`)

- CSP gắn trên `next` / `rewrite` / default product path qua `withRuntimeCsp`.
- **Lưu ý (nit, không chặn):** response `redirect` (marketing host, portal dual-run, `/gate`→`/auth`) **không** set CSP — giống hành vi trước khi CSP chỉ ở `headers()` cho document paths; tài liệu HTML chính vẫn qua nhánh có CSP.
- Matcher proxy loại static `/_next` và file tĩnh — CSP document do HTML route nhận từ proxy; phù hợp mô hình Next.
