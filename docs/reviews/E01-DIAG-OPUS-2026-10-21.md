## Kết luận

1. **«Đang tải…» 20–40s ở retest 11 là ARTIFACT đo, không phải server treo.** Server `guards_ok` 11–55ms; HTML đầy đủ tới trình duyệt < 0.5s. Nội dung cổng đã nằm trong DOM (`<div hidden id="S:0">`), nhưng React Fizz chỉ hoán đổi fallback → nội dung (`$RC` → `$RV`) trong **`requestAnimationFrame`**; webview Orca **không vẽ frame** (rAF ≤ 1 lần/giây, `first-paint` = **9940ms**) → `app/loading.tsx` đứng tới khi có frame (vd. `orca screenshot`). Tái hiện trên prod và local.
2. **401 sau login là BUG hạ tầng thật (P0).** Stack `vemoki-pre-*` gắn vào cùng network `nginx-letencrypt_nginx_network` với service name trùng (`api`, `web`, `keycloak`, `portal`) → `http://api:3001` của web/portal prod resolve ra **cả API prod lẫn API pre**; socket keep-alive dính API pre (issuer `pre-auth.vemoki.com`) → mọi token prod bị 401 trong 3–5ms. Hết lúc **11:07:54Z (VPS)** khi stack pre bị gỡ — không do PR nào.
3. **Vòng lặp vô hạn là BUG web (P1).** Fail-closed không có điểm dừng: sau một lần refresh, 401 tiếp theo → `/auth?next=` → login → SSO Keycloak tự cấp token → callback → `/gate` → 401… (~2.9 vòng/giây, > 1 100 vòng/10 phút).
4. **D02 «Thiếu phạm vi sự kiện» là BUG thật (P1), độc lập với E01.** Luồng `/redeem?tenantSlug=…&eventSlug=…` không bao giờ điền `tenantId`; BFF trả 422 `SCOPE_REQUIRED`.

## Trả lời hai câu hỏi

### (1) #707 hay #711 làm hết 401? — Không PR nào

- Trước khi stack pre lên (08:39–08:41Z VPS), 401/kẹt là lỗi code thật (token stale + `cookies().set` trong RSC — `docs/reviews/E01-GATE-SSR-TRACE-2026-10-21.md`); #703/#707 sửa đúng phần đó. Sau 08:41Z, 401 đến từ **định tuyến sang API pre** — PR web không chạm được.
- Retest 11 (B04 + run1–5, 10:20–10:24 VPS) `guards_ok` 32–48ms vì sau khi deploy #711 restart web (10:16:38Z) socket tới API prod (172.23.0.7) — do pool kết nối, không nhờ guard `aud`. Từ **10:39:27 VPS** socket chuyển sang pre (172.23.0.11) → 401 100% → loop tới 11:07:52.
- Token bị 401 đã được chính callback web xác minh `aud=ticket-api` + chữ ký JWKS prod (`acceptOidcTokenGrant` trong `apps/web/app/api/auth/callback/route.ts`). Vì vậy giả thuyết "thiếu audience" (`docs/reviews/E01-GATE-TOKEN-B-1021.md`) không phải nguyên nhân 401 trên prod; guard `aud` của #711 vô hại nhưng không tác động.
- #711 cũng **không** chặn loop: hình dạng loop sau #707 (09:30–09:5x) và sau #711 (10:3x–11:0x) giống hệt (bảng E5).

### (2) Vì sao D02 báo «Thiếu phạm vi sự kiện»? — `tenantId` rỗng khi submit

## Ghi chú khác (không chặn E01)

- **P2 ops:** đồng hồ VPS chậm ~160s → bật NTP (chrony / systemd-timesyncd). API có `clockTolerance` 300s nên JWT chưa lỗi, nhưng đối chiếu log rất dễ sai.
- **P3:** nginx `proxy_buffering on` gom stream thành một lần gửi — không gây chậm (upstream xong trong ms) nhưng khiến ART-1 luôn xảy ra trong webview không vẽ frame.
- Số đo hạ tầng "web→api 76ms" trước đây có thể đã đi vào API pre — đo lại sau BUG-1.
- `/api/bff/platform/me` 401 mỗi lần tải trang với staff không phải operator là fail-closed đúng thiết kế (chỉ là nhiễu log).
- **Tuỳ chọn hardening (cần ADR nếu làm):** `app/loading.tsx` ở gốc bọc mọi route → trang nào chưa có dữ liệu lúc flush shell đều phụ thuộc rAF để reveal. Nếu muốn `/gate` chạy được trong kiosk/webview không vẽ frame: chuyển `loading.tsx` vào route group không chứa `/gate` để HTML `/gate` blocking (+~20–50ms TTFB), đổi lại client navigation tới `/gate` mất loading UI tức thì.
