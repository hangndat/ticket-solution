2. **App DB (backend helpers in `vemoki-runtime`, `DATABASE_URL` from worker)** — `upsertFromVerifiedIdentity`, staff `STAFF` membership + event assignment, inventory codes `UAT-DEVICE-G01`–`G04` (quota-checked), redemption via `redeemAndIssueTicket` (official issue path).
3. **QR artifacts** — `renderCredentialQrPng` + `ticket_credentials` (credential v1), written under `/opt/vemoki/secrets/uat-g/`.
4. **Verify (no secrets in logs)** — ROPC `ticket-web` → `GET /v1/me/tickets` (**4× `ACTIVE`**), staff `POST …/sessions` then `POST …/sessions/revoke` with `staffSessionId` (**201**, no confirm).

## Commands (redacted — run on VPS `conanphong`)

```text
# Secrets dir
mkdir -p /opt/vemoki/secrets/uat-g && chmod 700 /opt/vemoki/secrets/uat-g

# Keycloak admin + user provision (passwords → uat-g-credentials.txt only)
docker exec vemoki-keycloak-1 /opt/keycloak/bin/kcadm.sh config credentials \
  --server http://localhost:8080 --realm master --user "$KEYCLOAK_ADMIN" --password "<redacted>"
# create users uat-g-attendee@ / uat-g-staff@, set-password, requiredActions=[]

# DB seed (subjects from kcadm, env from /opt/vemoki/.env, DB URL from worker)
DB_URL="$(docker exec vemoki-worker-1 printenv DATABASE_URL)"
docker run --rm --network vemoki_internal --env-file /opt/vemoki/.env \
  -e DATABASE_URL="$DB_URL" -e ATTENDEE_SUB="<kc-sub>" -e STAFF_SUB="<kc-sub>" \
  -v /opt/vemoki/src:/app -v /opt/vemoki/secrets/uat-g:/secrets/uat-g \
  -w /app vemoki-runtime:local node scripts/seed-uat-g-prod.mjs

# Verify
docker run --rm --network vemoki_internal --env-file /opt/vemoki/.env \
  -v /opt/vemoki/secrets/uat-g:/secrets/uat-g -v /opt/vemoki/src:/app \
  -w /app vemoki-runtime:local node scripts/verify-uat-g-prod.mjs
```

If Keycloak users are recreated and `sub` changes, sync `users.subject` for the two emails (issuer prod) before wallet/gate verify — app rows are keyed by internal `userId`, but OIDC must match `sub`.
